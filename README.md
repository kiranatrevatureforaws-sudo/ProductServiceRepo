# Product service

Spring Boot REST API using Java 21. Products are stored in an in-memory List in
ProductServiceImpl, which implements the ProductService interface. The list starts
with five sample products (IDs 1-5), and new IDs start at 6. Restarting the
application restores the sample products and discards runtime changes.

Run with `mvn spring-boot:run` and test with `mvn test`.
The default port is 8081; override it with the `SERVER_PORT` environment variable.

| Method | Endpoint | Result |
| --- | --- | --- |
| POST | /api/products | Create a product (201 and Location header) |
| GET | /api/products | List products (200) |
| GET | /api/products/{id} | Get a product (200) |
| PUT | /api/products/{id} | Replace a product's fields (200) |
| DELETE | /api/products/{id} | Delete a product (204) |

POST and PUT accept this JSON body. IDs are generated by the service.

```json
{
  "name": "Laptop",
  "price": 999.99,
  "category": "Electronics"
}
```

Name and category must be nonblank; price is required and must be nonnegative.
Invalid requests return 400, and missing products return 404.

## Docker

The multi-stage Dockerfile builds and tests the project with Maven and Java 21,
then runs the packaged JAR on a Java 21 JRE as a non-root user. A local Java or
Maven installation is not required; Docker must be installed and running.

Run these commands from the project root:

```sh
docker build -t product-service:1.0 .
docker run -d --name product-service --restart unless-stopped -p 8081:8081 product-service:1.0
curl http://localhost:8081/api/products
docker logs -f product-service
```

To use another host port, for example 80, change the mapping to `-p 80:8081`.
If overriding `SERVER_PORT`, also change the container side of the mapping:
`docker run -d --name product-service -e SERVER_PORT=9090 -p 9090:9090 product-service:1.0`.

## Deploy later on AWS EC2

For an Amazon Linux 2023 instance, connect over SSH and install/start Docker:

```sh
sudo yum install -y docker
sudo systemctl enable --now docker
```

Copy this project's source, `pom.xml`, `Dockerfile`, and `.dockerignore` onto the
instance. From that project directory, build and run:

```sh
sudo docker build -t product-service:1.0 .
sudo docker run -d --name product-service --restart unless-stopped -p 8081:8081 --log-opt max-size=10m --log-opt max-file=3 product-service:1.0
curl http://localhost:8081/api/products
```

In the instance's security group, allow inbound TCP port 8081 from the client IP
addresses that need access. Allow SSH port 22 from your own IP. For direct access
from the internet, the instance also needs a public IP and a subnet with an
internet gateway route. Then call
`http://<EC2-PUBLIC-IP>:8081/api/products`.

The build needs outbound access to Docker Hub and Maven Central. Building on the
instance produces an image for its CPU architecture. If you later build elsewhere
and push to a registry, build for the EC2 architecture (amd64 for x86 instances,
arm64 for Graviton).

The API currently has no authentication. For a public production deployment,
add authentication and HTTPS, such as through a load balancer, and restrict direct
instance access. Product changes remain in memory and reset whenever the container
or application restarts; a Docker volume does not persist this List.

References: [Docker multi-stage builds](https://docs.docker.com/get-started/docker-concepts/building-images/multi-stage-builds/)
and [AWS Docker installation on Amazon Linux 2023](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/create-container-image.html).
